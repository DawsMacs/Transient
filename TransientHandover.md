**The baby** (`baby school` / `baby ask` / `baby learn`) is one system:

1. Taught **units of lessons** (the teacher groups them, never says how to learn them), or finds the units itself (`baby discover`; fails on real text, see section 10).
2. For each unit it chooses how to learn it **from facts it holds back**: *remember* (voting memory), *rule* (robust ridge fit), *select* (bigger/smaller), *program* (searched expression, learned library, competing explanations; and now **partial programs** that fit most lessons and only ever guess), *network* (rarely).
3. **Questions** go through: unreadable numbers refused -> a word never met refused (except for a partial-program unit) -> routed by a sparse incremental table with a **recognition floor that follows the margins as it learns** -> the unit's mechanism answers.
4. **Careful by default** (Daws): it states as fact only what lies inside the range taught *or checked* (the **reach**: lessons that ask for the *same function* must cover every number of the question, a staircase not a box). Beyond that it offers a **labelled guess** with a stated hit rate (never an `answer`), or nothing.
5. **It asks and checks itself** (`wonder`, `check_myself`: edges, corner, and the frontier of what can be asked) and learns the answers; a simulated teacher makes ~5-7 questions per numeric unit enough to turn every refusal the reach rule causes into a stated fact.
6. **Skeptical of its teacher** (on by default since 2026-10-22): an answer to one of its own checks that contradicts a settled rule is **held**, not learned, until repeated (`Learned.disputed`; held answers are saved in the school file). An established exact program survives up to 3 contradicting lessons.
7. It estimates its own noise and sets its own reliability bar; keeps learning after school (surprise gate, pen, `reorganise`/`sleep`, `--compact`).

## 6. Guards that must stay (each one was learned from a failure; do not "simplify" them away)

- **Behavioural uniqueness / believability:** a built program is trusted only where its smallest fits agree (`alts`), and only if the lessons carry more bits than the search spent. A *partial* program must also pay for naming each exception (MDL), and **answers only as a labelled guess, never a fact; it is never library vocabulary; it counts as an open unit** (revisited when the library grows: `capsum` regression).
- **Reliability bar** adaptive, floor 0.8, 0.9 when clean. A mechanism below it must not answer.
- **Memory:** votes among matching lessons (a tie refuses), content words compared as a sequence with repeats, number words never glue; lesson identity = words in order.
- **Library:** only *settled* programs are vocabulary; a unit is never explained by its own contributions; a unit contributes a behaviour once.
- **Cross-validation:** facts that share a bag of words in one fold; merge parts stratified.
- **Unreadable numbers** refused at `ask`, at the CLI entry and when teaching; **never ask for an answer it cannot read back**.
- **Reach is a staircase over lessons that ask for the SAME FUNCTION** (rule: total word-weight vector; selection: sign; program: all). **Never define "which lessons count" by a glue heuristic** (it moves as facts are added, so teaching more reduced coverage) and never by the rule's `all_ops`/`active_ops` words (template words like "what"/"is" carry weight).
- **A box of per-operand ranges vouches for unchecked corners** (two confirmed edges covered the corner between them: 4 wrong facts): keep the staircase.
- **A guess is never an `answer`**; every harness counts right/wrong on facts alone; guesses are scored apart with a stated, calibrated rate.
- **A lesson that contradicts a rule outside what the rule explains refutes it there** (no guess beyond its explained reach); what it was told wins over a refuted rule.
- **A repaired program never lets its repair lessons vouch for their neighbours** (one point fits many laws: a cap at 24 explains 24+12=24 as well as a reflection at 30), **and must agree with the old rule everywhere inside the range the other lessons cover** (a coincidental program once rewrote a selection unit and stated 240 wrong facts). **After ANY change to repair, re-run `compare --teacher 200 --wrong 0.2 --persistent`: it must read ~87.3 % right, ~42 wrong facts all repeats, 0 elsewhere** (it read 88.0 % / 28 before the repair step and 87.97 % / 25 before `refuted` used the staircase; the 5 % persistent run reads 99.11 % / 4) (there is no unit test for the inside-range guard). The reach functions' `skip` lists must be sorted (`binary_search`).
- **Skeptical by default** for the baby's own checks; **callers of `learn_wondered` must handle `Learned.disputed`** (ask again), or use `learn_wondered_sure` when modelling a teacher who repeats themselves.
- **The recognition floor follows the margins** (stored ratio to the leave-one-out margin), never above its teaching-time value.
- **The energy meter:** the idle baseline is re-measured **before every measurement**, the lower of before and after is used, a non-positive reading is "n/a" (never 0.00 J), no CPU-share scaling, a warning when other processes use >25 % of the busy CPU time. Quiet machine required for clean figures.
- **Report WRONG apart from refused, and deceptive kinds apart from the 0-wrong headline.** Add must-refuse questions with every capability (the same ambiguity family bit **four** times).
- **Wrong facts are accounted by fact (unit + numbers, any phrasing)**, not by exact question text, when deciding "repeat of what it was told" versus "damage elsewhere".

## 9. Doubts and honest caveats (state these when reporting; they are not boilerplate)

- **Almost everything is synthetic and tidy**, in number words, in rule-shaped units: the baby's home ground. "0 % wrong" is a spot check plus must-refuse batteries, not a proof; **every harder test found a new hole** (regime changes, corners, glue, stale meters, wrong teachers). Expect more.
- **The simulated teachers**: errors are uniform over other number words, independent of difficulty; a real person repeats themselves more (the "persistent" column bounds that); one world and one seed for most noisy-teacher figures.
- **The language is mine**: mechanisms, operations, thresholds (see the list in section 8). The baby builds and selects inside them.
- **Energy figures are measurements to within about +-30 %** on a busy desktop (see the meter guards), and my own *estimates* were far off. Transformer comparisons use a plain-Rust transformer, no real sweep except 24 PyTorch settings.
- **The transformer overtakes the baby on raw accuracy for unseen questions from 60 units** (100 % vs ~90 % at 1,000 units) because careful mode makes the baby refuse ~9 % there; the baby's advantage is honesty, extrapolation, no forgetting, and teaching cost, **not** raw unseen accuracy.
- **Real text is mostly unsolved**: SVAMP is adversarially built; routing by words caps near 60 %; nothing shows behaviour on millions of real sentences or at "frontier" quality. Treat that as the open frontier, not a settled conclusion either way.

## 10. Failures, dead ends and wrong beliefs (chronological; read before you repeat one)

*Earlier sessions (kept short; the details are in `baby/README.md`):* the apart / minus / "N less than ten" ambiguity bit **four** times (a coincidence "explaining" a tens digit, primality "explained" by chance); a bluff "-3 plus 5 = 8"; a network trained per plain table inflated teaching cost; a cross-validation flaw let memory peek through word-bag twins; the first cost numbers were inflated by a bug that treated "five minus two" and "two minus five" as one lesson; a clean 600-unit world was only 89.7 % right *after* reorganising until fixed.

*This session (2026-10-21/22), in order, each with what it taught:*
1. **Pushed a commit with a failing test**: a command chain `cargo test | grep ... && git commit` commits even when tests fail (grep matches "FAILED"). *Gate commits with `if ... | grep -q "test result: ok. N passed"`.*
2. **Flipping careful on made the invention battery read "0 of 32"** with no error anywhere (it grades beyond-range questions, which careful refuses). *Capability batteries run permissive on purpose and say so.*
3. **My first experiment built a fresh school per kind and timed out**; a blanket text replace added a field to function signatures. *Use one school; anchor replaces uniquely and build at once.*
4. **One correction did not fix its neighbours** (303 of 305 stayed wrong, 2 became WRONG facts): the 5 % allowance for wrong lessons absorbed a correction *outside* the taught range as noise. *A lesson that contradicts a rule beyond its explained reach must refute it there (`refuted`).*
5. **A box-shaped reach vouched for unchecked corners** (4 wrong facts of 9,309). *Staircase, found by the calibration run, not by reasoning.*
6. **SVAMP, first run: nothing learned**; I first blamed number words in the stories (1 of 351 problems): wrong. The real causes: a program needed to fit *every* lesson, unmet words blocked the unit's own evidence, and >2 numbers made the search give up. *Measure the guess before building on it.*
7. **A regression the short batteries missed:** after partial programs, `invent --careful` read deceptive 309/411/0 instead of 521/199/0; a bisect with temporary switches showed a partial program counted as *settled*, so a unit that used to be revisited stayed a guess. *Run the long battery; bisect with env switches; remove them.*
8. **I blamed the wrong commit** for a 2 %-noise accuracy drop (98.0 -> 95.9 %); building the previous commit in a `git worktree` showed it was the earlier staircase change. *A/B against the committed binary before attributing.*
9. **The energy meter was wrong four times:** (a) one idle reading at start, with the browser and desktop at 30-70 % of the CPU: inflated figures; (b) CPU-share scaling "fixed" repeatability but under-counted (package power does not split by CPU time); (c) a stale baseline made later readings **0.00 J** (impossible) when the background went quiet; (d) the zero returned once more. *Re-measure the baseline per run, take min(before, after), report invalid as n/a, require a quiet machine, and distrust energy windows under 200 ms. The scale report never printed the meter warning at all until I noticed.*
10. **My counted energy estimates (45 nm) were 34-116x below the measurements**, and not uniformly. *Use measurements; the ledger's ratios are not to be trusted alone.*
11. **"The baby's energy advantage shrinks with scale"**: from three sizes and a noisy short reading. Withdrawn: five sizes gave 20x, 9x, 10x, 32-253x. **"It refuses more as it grows"**: from one lucky seed-1 world (3 % at 20 units; the ten-seed mean is 7.8 %). *Never conclude a trend from one seed or three points; run the other seeds before explaining.*
12. **PyTorch on CPU was slower than my plain Rust** for models this small (I had worried my Rust was the slow side), and a 24-setting search did not improve the transformer on unseen questions.
13. **Check probes silently vanished** when their answer could not be said (10 + 5 on a number line ending at ten): whole operations stayed refused (Sum 1,080 of 1,080). Fixes in order: step back toward the edge; probe the frontier of what can be asked; reserve places for the frontier (program units' in-range gap questions starved it).
14. **Teaching more REDUCED coverage:** the reach used lessons sharing a non-glue word with the question, and what is glue moves as facts are added ("equals" stopped being glue at the 32nd fact, so the check answers, phrased without it, stopped counting). *Never base a definition on a statistic of the data that changes as it grows; use the function the question asks for.* Two intermediate attempts failed: `all_ops` matches every lesson, `active_ops` includes template words; a merged-family test (minus not vouched for by plus) caught both.
15. **Recognition floor:** learning shrank small units' margin (0.99 -> 0.36) below a floor fixed at teaching time. *Attempt 1* (keep the floor a fixed fraction of the margin of the baby's *own taught lessons*) **did not work** and was reverted (taught lessons keep large margins; unseen questions collapse). *Attempt 2* (a fixed ratio to the **leave-one-out** margin) works. *Its trigger (20 % total growth) never fired* because the growth was 6 % but concentrated in 400 small units; *and the check answers don't come through the end of `learn`* (early return), so the trigger had to be in `learn_wondered` too.
16. **A test hung for minutes**: it taught lessons that break a unit's rule, forcing a slow full re-fit each time. *Tests should teach lessons that fit.*
17. **Program tolerance went into the wrong function first** (`relearn_unit`; numbers did not move); the real path was `refit_in_place`. *When a fix changes nothing, print the damaged units instead of reasoning.*
18. **"Damage elsewhere" was mis-accounted** (exact question text): the "6 wrong facts elsewhere" were other phrasings of a fact it was wrongly told. *Key facts by unit and numbers.*
19. **Persistence bug:** the file stored `unit, answer, question`, the loader read `unit, question, answer`; a test of the save/load round trip caught it.
20. **Tooling slips:** a cargo test filter written as a regex ran zero tests and reported success; two tests carried a meaningless `|| true`; copying a binary failed with "Text file busy" because stale experiment processes were still running (and a stale shell loop kept starting the old binary: kill the loop by pid first); `git stash` for a timing A/B must be popped; `sleep` chains are blocked.
21. **Repair, same day:** (a) my "no repair possible" test used one arbitrary correction and the repair found `mod 29` (a legitimate wrap: no taught sum reaches 29): *a lone number is a wrap somewhere; test with two contradictions no small law shares.* (b) The reach functions' skip lists need sorting (`binary_search`); unsorted, the skip silently did nothing (the debug print showed identical hulls). (c) **A repaired program let its repair lessons vouch for the questions below them**: one point is consistent with many laws; fixed with `ProgramRule.repaired`. (d) **The sometimes-wrong-teacher run found what nothing else did**: 270 wrong facts (240 elsewhere) from a selection unit repaired into a coincidental program that disagreed with the true rule inside its taught range; the fix is the agreement guard; *the long capability batteries all read fine while this was broken: run the wrong-teacher experiment after any change to what a contradiction can do.* (e) **Winning the facts back, found by a per-kind tally against the pre-repair commit in a `git worktree`:** a small unit re-decided on one contradiction fell to memory before the repair could run; a repaired program with rivals was discarded as "open"; and my own invent harness filtered out the new question (it only passed edge questions). *When a total moves, tally per kind against the old build and trace the one kind.* (f) **Real text routing, same day:** my "bag-of-words ceiling" belief came from the family of classifier I had tried (counting); a mistake-driven learner broke it. *A ceiling measured with one family of method is not a ceiling of the data.* My first perceptron was fed in unit order and scored below the majority class: *a result below the majority class is a bug.* Corrections ON TOP of the counts were worse than counting (scale mismatch); the pure learner works. (g) **Number selection, same day:** local context alone is no better than before (39 %); the cue that matters is whether the words beside a number occur in the QUESTION, found as the last sentence of the string, not as a fixed window; stated rates were over-confident (77 % stated, 32 % right) until the baby checked itself on held-back answers. **`--seed` placed before `--select` was swallowed as its value, so three "seeds" were seed 1: identical outputs are a clue; put flags last.** (h) **`refuted` used the per-operand box, so a wrap that shows itself only at a corner was never repaired** (the box-vs-staircase hole again, a second place; found by tracing `wrapsum`, which had 0 of 62 stated); fixing `refuted` alone changed nothing because the repair's agreement guard also checked the whole box: *the same hole can sit in several places; grep for every use of `operand_hull`.* Cost: a wrongly-labelled corner now looks like a regime change (persistent teacher -0.5 pt). (i) **ASDiv, same day:** problems with zero or one readable number poison a unit (set aside now); my problem counter counted digits only while the baby reads words, so "two-number" sets had hidden distractors: after fixing it, SVAMP's six-split figures are lower and swing 35-73 % (mean 56 %; I had reported 63 %) on whether a unit clears the 0.6 guess bar. *Re-measure old figures after changing how a set is defined.* `review_programs` re-ran the whole cross-validation of every unit when the library was empty (222 s -> 111 s, identical output). (j) My shell launched four background jobs with `S=...` set inside a backgrounded chain, so they ran nothing: check the output files exist and grow.
22. **Dead ends worth knowing:** a learned number selector for 3-4-number problems (36-38 %, ceiling 63 %: low yield); ~~a bag-of-words classifier cannot route SVAMP's operation better than ~60 %~~ (WRONG: that was naive-Bayes-style counting; a perceptron on the same bag of words gets 78 %, with the last words marked 80-82 %); the discovery mode shatters real text into units named after story words.

## 11. How to work on this (earned the hard way)

1. **Measure before building, and print the cases behind every number** (the debug env vars above). Several of my first explanations were wrong. Record mistakes as they happen in `baby/README.md` (Daws values this).
2. **Ask adversarial questions after every capability** and keep must-refuse batteries in the tests; build the harder test *before* the feature.
3. **Long experiments:** the tool times out at ~590 s. Run them in the background to a file (`nohup sh -c '...; echo FINISHED >> file' &`), **delete the file before a rerun**, wait with the `Monitor` tool on an until-loop. **A monitor expires after 10 minutes** (re-arm; check the files; the expiry notification is not a failure). **Copy `target/release/baby` to a scratch name before a long background run** so rebuilding cannot disturb it. Rough costs: `invent --seeds 8` ~2.5 min; `invent --careful --seeds 3 --rounds 2 --limit 4` ~15 min; `scale --sweep 20,60,200,600` ~5 min; `compare --scale 600` d=32 ~10 min, 1,000 units ~28 min; PyTorch 24-setting search ~10 min per seed.
4. **Never `pkill -f "<pattern>"` where the pattern appears in your own command line**; use `pkill -x <name>` or kill by pid. Check for stray loops with `pgrep -af`.
5. **Timing and energy need a quiet machine and no parallel jobs** (8 cores: parallel runs are fine for correctness only). Ask Daws to close the browser.
6. **Tool pitfalls:** piping a CLI into `head` can kill it before it saves; scripted find-and-replace needs unique anchors; the Write tool needs the file read first; `then_some` evaluates eagerly; cargo test filters are substrings, not regexes; read the build output (an `error` line the `grep` missed once cost a round).
7. **Keep `TransientVision.md` Daws's voice.** Append dated entries as he gives them; assistant context in separate labelled sections; update the progress log at the end of each stretch.
8. **Privacy / repo is public:** never commit `.local/` or the sibling project's details; data files (SVAMP) are never committed. Use `git status` / `git log --stat` before `git add -A`: other agents commit to this repo too.
9. **Gate every commit on the tests passing**; build the failing test first when fixing a hole; commit with the `Co-Authored-By` trailer the harness specifies; push to `origin main`, then check `gh run list` for CI (the run whose `headSha` equals `git rev-parse HEAD`).
10. **When Daws asks for analogies, give them** (the baby as a student with study methods; the scientist who guesses, tests, and updates; the contestant who passes rather than bluffs).
