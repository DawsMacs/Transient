# Novice

The main line of work in Matter, **rebuilt from scratch**. [`baby`](../baby/README.md) is frozen as the reference and the measuring stick; Novice shares no code with it. What carries over is the [entry exam](../baby/README.md) (a plain-file and line-protocol judge that any system, in any language, can take), the goldens-and-platform habits, and the rules below.

> **Status (2026-10-25): started; rungs 0 to 4 done on the tidy adaptive exam.** It finds the kinds of question itself, explains most of them with programs priced in bits, builds later explanations from earlier ones, states no wrong fact, knows how reliable each source has been, and with one source states a teacher's possibly wrong answers as guesses, not facts (with a second independent source, as facts when the two agree). See "Results so far" for the numbers and, just as important, for what they do not show. On the same exam it uses about 55 times less energy than baby (3.7 to 4.2 J against 221 to 226 J; see "Joules"), after its cost of learning was cut 25-fold from the first version.

Labels used below: **Hypothesis** (believed, not shown), **Measured** (a number from a run), **Open** (not started).

## What Novice is for

Two things, and a bet that they help each other.

1. **Recursive meta-adaptive learning that is genuine.** baby adapts, but inside a design that was written for it: a menu of five mechanisms, an expression language of seven pieces, and thresholds chosen by hand. The test for "genuine" is a capability that no line of code names in advance, shown on a task the system was not built for. Novice is built so that its own language can change when the old one fails.
2. **Efficiency from the start.** Every milestone has a joule budget and a measurement. baby answers a question for about 59 µJ but pays about 36 mJ to absorb one told answer (about 600 times more), and nothing it learns makes later answers cheaper. **Hypothesis (the bet):** adaptation can make a system cheaper to run, not dearer, because learning is compression and a shorter explanation costs fewer operations to evaluate. If that holds, the cost of answering falls as the system gains experience, and the cost of learning pays itself back.

Where the two truly conflict, adaptation wins and the cost is written down. "Frontier" is an ambition, not a claim: nothing here is near it.

## Design (all Hypothesis until a rung measures it)

- **One currency: bits.** An explanation is a program, or a table of facts. To compare two explanations, Novice adds the bits needed to write each one down to the bits needed to write down what it gets wrong (the minimum-description-length idea). A contradicting answer is not "held" or "vetoed" by a special rule; it is data that costs the incumbent explanation some bits and may cost a rival fewer. Where baby needs a hand-set count (three coherent answers before it believes a rule has changed), the count should fall out of the costs. That is the first thing to test (rung 3).
- **Integers in every decision.** Costs are counted in 1/256 bit with integer arithmetic only ([`bits.rs`](src/bits.rs)). Nothing that decides an answer uses the math library, so results are identical on every platform by construction instead of by testing it thirteen times. Floating point appears only in reports.
- **No labels from the teacher.** The exam tells a system which unit and which fact every lesson belongs to. Novice's protocol layer drops those columns before the system sees them ([`protocol.rs`](src/protocol.rs), tested), so structure has to be found, not read.
- **Sources are first-class.** When the exam says who is speaking (an optional extra column), Novice keeps a record per source and believes by agreement of independent sources or by an explanation it can check. With one source it claims nothing more than one source can give.
- **The language is a learned thing.** The starting primitives are few. Pieces that keep appearing in good explanations are promoted into the language, which makes later explanations shorter (and cheaper to run). Which primitives it starts with is a choice of mine, the largest remaining hand-built part, and is written down as such.
- **Cost proportional to the change.** A told answer should touch only what it concerns. The measure is joules per told answer staying flat as the world grows.
- **Zero dependencies, en-US, Rust.** Builds offline.

Prior work this leans on, so nobody mistakes it for new: the minimum-description-length principle (Rissanen) for the currency, and library-learning program synthesis (the DreamCoder line of work) for a language that grows by compressing its own solutions. What is meant to be different here is the setting: online, integer-only, a joule meter on every step, source tracking, and an exam that does not hand over the structure.

## How it is judged

`baby exam adapt-write DIR` writes a stream of lessons and questions; `baby exam adapt-drive DIR COMMAND...` runs any system as a child process and judges it. For Novice:

```bash
cd novice && cargo build --release --offline
cd .. && cargo build --release --offline
./target/release/baby exam adapt-write /tmp/exam --seed 1
EXAM_NO_JOULES=1 ./target/release/baby exam adapt-drive /tmp/exam "$PWD/novice/target/release/novice" serve
```

The judge reports wrong facts (must be 0), facts and guesses right per kind of question, and how each kind changes from the first third of the stream to the last. Rung 0 refuses all 787 questions, so the judge's last two lines read:

```
WRONG facts over the whole stream (must be 0): 0
verdict: PASS on honesty; compare coverage and the climb across the thirds
```

## The ladder

Each rung has the test that would show it works, and a joule line to fill in.

| rung | what | test | status |
|---|---|---|---|
| 0 | speaks the protocol, refuses everything | 0 wrong facts; the exam can drive a system that is not baby | done |
| 1 | remembers what it was told (a table of facts) | 0 wrong facts; right on the facts it saw, refuses the rest | done (inside the learner; the four lookup kinds in the exam are tables) |
| 2 | finds programs from a minimal start | right on questions it never saw, for kinds a short program can say; routing found without the labels | done on the tidy exam (seeds 1 to 3); joules open |
| 3 | rival explanations scored in bits | on the 14 streams of baby's wrong-teacher work: as few believed mistakes as baby's, with **no tuned count** | done on the tidy exam: repeats on par with baby's, 0 elsewhere, at a cost in coverage (see above); the count of three falls out of the costs |
| 4 | sources | with a second, right source added, repeats fall in kinds that have no law to check against | done on the tidy exam: 0 wrong facts of any kind on all streams with one reliable and one unreliable source; with one source, repeats fall to 0 by stating the unreliable source's answers as guesses |
| 5 | the language grows | a kind that needs an operation Novice does not start with, from worlds written apart from the learner, solved by a primitive it made | development set: 5 to 7 of 18 hard kinds per seed acquired; blind set: 1 of 16 on two seeds, 0 on the third, 0 wrong facts either way (see "The blind test of rung 5"); after extending the mechanism with the second set in view: digit sum on 3 of 3 seeds; the third blind set: 0 of 15 hard kinds on every seed, controls mostly refused, 0 wrong facts (see "The third blind test") |
| 6 | answers get cheaper | joules per answer on a fixed set of questions fall as it learns, wrong facts stay 0, and the break-even point (learning joules spent against answer joules saved) is reported | first steps: learning cost 25-fold lower than the first learner, composition 116 times cheaper than enumeration, joules measured once; the curriculum measurement shows capability from experience but not yet a falling cost |

Rungs 0 to 4 are the first milestone (the tidy exam, with a source tag). Rung 5 is the test of "genuine"; the worlds for it are written by a process that the learner's author does not read until the review, so the learner cannot be tuned to them. Rung 6 is the bet itself.

| 1 | baby | 0 | 64.2 % | 1.5 % | 11.4 % | 85.2 → 87.8 % | 15.6 s |

| 3 | baby | 0 | 64.4 % | 1.5 % | 11.2 % | 86.7 → 89.7 % | 16.9 s |

The kinds that change their rule outside what was taught (a sum that saturates at 30, one that wraps at 40) climb from 72.0-84.4 % right in the first third to 96.2-100 % in the last in Novice (seeds 1 to 3), and from 68.0-78.1 % to 92.3-97.4 % in baby. The 11.2 % refused are the same in both: the six kinds that have no rule it can say (a prime test, an exclusive-or, four arbitrary codes), which cannot be answered before they are told.

Two kinds became words (sum of squares, average); the other 37 explained kinds did not.

### Joules (first measurements, 2026-10-25)

The CPU package's own counter (RAPL), joules above the machine's idle draw, on the seed-1 adaptive exam, one desktop core. Novice is measured as a child process through the exam's protocol, baby in-process; "stream" is answering the 787 questions *and* absorbing the truth told after each, because for both systems that is one loop.

| | teaching (3,048 lessons) | stream (787 questions, truths told) | total | right answers per joule |
|---|---|---|---|---|
| Novice (4 runs) | 3.3 to 3.8 J (0.33 s) | 0.36 to 0.42 J (0.03 to 0.06 s), about 0.5 mJ per question | **3.7 to 4.2 J** | 164 to 184 |
| baby (3 runs) | 121 to 123 J (10.3 s) | 100 to 104 J (8.7 to 8.8 s), about 130 mJ per question | **221 to 226 J** | 3.0 to 3.1 |

So about **55 times less energy for the same exam**, with 689 right answers against 685. Caveats: these are upper bounds (the counter includes whatever else the machine was doing: it warned of other processes during every run, and Novice's runs last a third of a second, so a background process weighs heavily in them); it is one machine, one seed, and the clean exam; baby's own notes recorded 65 J on 2026-10-23, before its skeptical exam driver, and today's build measures 221 to 226 J in each of three runs; and the comparison is of two systems that learn differently, not of one idea against another. What it does show is that Novice's design is not just faster in wall time: it is cheaper in energy, by a margin that survives the noise. Nine tenths of Novice's energy is teaching (the first search for programs); absorbing a told answer costs it a fraction of a millijoule, a few thousandths of baby's. That is still not the thing the efficiency bet claims (that *adapting* makes a system cheaper): nothing here yet shows its energy per answer falling as it learns.

### Sources (rung 4)

`baby exam adapt-write DIR --second P` (the exam extension in its own pull request) adds a second source that is wrong about a fraction P of the facts, independently of the teacher's mistakes; `adapt-drive` then sends each truth twice, tagged `teacher` and `second`. Streams without it are unchanged.

**How it works.** What the lessons said and what each told source says are separate *channels*. A channel is as reliable as it has been wherever a program was confident (the only check a system can make on its own), starting from the lessons' record when it is the same teacher. In a kind with no rule, each channel that spoke contributes its reliability if it is right and `(1 - reliability) / (answers possible - 1)` if it is wrong, and the answer is believed as much as the channels jointly allow. A fact needs all but 2^-10 of the belief, as everywhere. So a single channel measured at 80 % can only be a guess; two independent channels that agree make a fact; two that disagree favor the more reliable one with a stated doubt. For a program, a second source's answer is independent evidence; the lessons followed by the same teacher's told answer are one speaker and are weighed once.

**Measured** (seeds 1 to 3, 787 questions, 0 wrong facts means none of any kind):

| streams | wrong facts | facts right | wrong guesses | refused |
|---|---|---|---|---|
| honest teacher (clean exam) | 0 | 67.0 / 67.7 / 67.9 % | 1.1 / 1.3 / 1.1 % | 11.3 / 12.2 / 11.7 % |
| teacher wrong about 10 %, 20 %, 40 %, **one source** | repeats 0 / 0 / 0 in all nine streams (before this rung: 1/0/3, 2/0/7, 9/9/7); one "elsewhere" at 40 % seed 2 | 61.8 to 63.7 / 58.1 to 61.0 / 46.1 to 52.1 % | 1.3 to 1.8 / 0.8 to 2.4 / 1.5 to 2.3 % | 11.7 to 12.6 / 14.6 to 20.3 / 28.2 to 36.5 % |
| teacher wrong about 20 %, second source wrong about 5 % | **0** on all three | 66.8 / 65.2 / 64.5 % | 0.9 / 0.9 / 0.6 % | 17.3 / 14.4 / 14.4 % |
| teacher wrong about 40 %, second source wrong about 5 % | **0** on all three | 66.5 / 64.2 / 63.4 % | 0.1 / 0.6 / 0.3 % | 29.7 / 23.0 / 20.8 % |
| honest teacher, second source wrong about 5 % | 0 | 67.2 / 67.3 / 67.6 % | 0.6 / 0.9 / 0.8 % | 11.2 / 11.3 / 11.2 % |
| teacher and second source both wrong about 20 % | 0 | 61.5 / 61.8 / 61.1 % | 1.3 / 0.9 / 0.8 % | 20.5 / 15.5 / 14.6 % |

The reliabilities it measures are close to the truth (seed 3 shown): with a teacher wrong about 20 % and a second source wrong about 5 %, it reports the second source at 478 of 497 checks (96 %; true 95 %) and the teacher at 283 of 358 (79 %; true 80 %); at 40 % the teacher at 215 of 349 (62 %; true 60 %). With an honest teacher (seed 1) it reports 367 of 367 for the teacher and 502 of 530 (95 %) for the second source.

**What this means, and what it does not.** With one source the remaining repeats disappeared because Novice no longer states what a source it has measured as unreliable says as a *fact*: it says it as a guess with that source's measured rate, so the mistakes are wrong guesses (1.5 to 2.4 %), which are allowed, and not wrong facts. That is the honest version of "a single source cannot catch these mistakes": it cannot catch them, but it can know it cannot. A second source turns many of those guesses back into facts when it agrees. The costs: under a wrong teacher with one source the facts it can state in the kinds with no rule fall, which is the correct price of not believing an unreliable source. The limits: the sources must err independently (two sources that make the same mistake are believed); the checks on reliability exist only where a program is confident, so a system with no kinds that have rules would have nothing to measure with; the answer space (100 possible answers) is a guess written into the code; and this is one tidy exam.

### Acquiring operations it does not start with (rung 5, first results on a development set)

`tools/hidden_worlds.py` (from a separate session, in its own pull request) writes exams in which every interesting kind needs an operation outside `+ - * min max div mod`: counting one bits, greatest common divisor, bitwise and/or/xor, integer square root, number of divisors, the smallest power of two above a number, trailing zero bits, bit mirror, last digit of a power, a small table; plus kinds composed on those (popcount plus a constant, parity of the bit count, gcd halved, lcm, hamming distance, sqrt plus popcount); plus controls the starting operations can say; plus arbitrary codes. Before any of this was built I ran the existing Novice on it once, unread: it refused every new-operation and composed question (0 wrong facts), and baby gave exactly the same numbers.

**What was added.** An explanation may now refer to the kind's *own values*: `f(p) = e(p, f(g(p)))`, with the base cases being the table of what was taught and told (shared and live, so what is learned later is used at once). The reduction `g` and the step `e` come from the same bit-priced search as everything else: reductions from everything three to five nodes can make, steps from a search over the arguments and the value at the nearer point. Nothing in it names counting, divisors or remainders. It is tried only when no closed form (plain search, constants, composition from learned words) explains the kind, and what it finds becomes a word like any other, so kinds built on it can be composed.

**Results on the development worlds (seeds 1 to 3):** 0 wrong facts and 0 wrong guesses on all three; the original exam is unchanged (same numbers, 0 wrong facts). Five of the 18 new-operation and composed kinds are acquired on each seed, and every one is correct (checked against the generator's `key.tsv`, which the system never sees):

| seed | acquired by a recurrence | acquired by composing on those |
|---|---|---|
| 1 | smallest power of two above x (`r + r, r = f(x - x div 2)`), count of one bits (`r + x mod 2, r = f(x div 2)`), one bits plus a constant, gcd halved (`r = f(y, x mod y)`) | parity of the bit count, as `mod(popplus(x), 2)` |
| 2 | count of one bits, one bits plus a constant, gcd and gcd halved (`r = f(mod(y, x), x)` and `r = f(y, mod(x, y))`) | parity of the bit count, as `mod(popcount(x), 2)` |
| 3 | gcd, count of one bits, smallest power of two above x, one bits plus a constant | parity of the bit count, as `mod(popcount(x), 2)` |

(In an earlier version it recovered the count of one bits from *popcount plus 2*, as `popplus(x) - 2`, after finding the latter first; the final version finds it directly.) What it gets right is stated as a labeled guess with a measured track record, not as a fact: 7 to 14 % of the new-operation questions and 26 to 31 % of the composed ones are answered correctly this way; the rest are refused.

**Not acquired, and why.** Trailing zeros (the step needs a conditional: seven nodes), integer square root and divisor count (no short recurrence), the table lookup (a period the reductions do not reach), bit mirror, and exclusive-or / and / or and what is built on them (the step is nine to eleven nodes). The last digit of `a^b` was found in an earlier version as `f(x, y) = f(x, y + 4)` (its true period) and was no longer found after I changed how reductions are ranked; lcm, hamming distance and sqrt-plus-popcount depend on operations it did not acquire.

**What I did to get here, and what it cost me.** The first version accepted a recurrence whenever it was cheaper than the table, and it stated **2 to 3 wrong facts per seed** from spurious fits (a recurrence that ignored the value at the nearer point and "explained" only the rows its own reduction selected; `f(x, y) = f(x + y, 3)` for bitwise-or). Each fix is recorded under "Mistakes". The three that matter: the table's cost was computed with a code that charges large numbers heavily, which overstated what a chance fit saves for kinds with small answers, so the table is now priced with a code that learns the answers' distribution; a recurrence is fitted again on three quarters of the table and must predict the hidden quarter (four rounds, at least three hidden points reached, none wrong); and an answer worked out by walking a chain of reductions is **never a fact**, only a guess whose confidence is how often such answers have been right.

**This is a development set, and I have read it.** I wrote the mechanism after reading the list of 25 kinds, so these results measure how well I did on a set I knew, not whether the mechanism generalizes. The test that counts is a second set, written without reading Novice's code and not shown to me before I ran it once. It has been run, and the result is below: much smaller.

### The blind test of rung 5 (a second set, run once)

The development result above was measured on a set whose kinds I had read. A second generator, `tools/hidden_worlds_b.py` (written by a separate session that did not read Novice's code; its own pull request, #33), has 23 different kinds: 11 that need a new operation (Euler's totient, number of distinct prime factors, the next prime, Fibonacci mod `m`, Collatz steps, partitions, Catalan mod `m`, base-3 digit sum, base-3 digit reversal, binomial mod `m`, Josephus), 5 composed on those, 4 controls the starting operations can express, and 3 arbitrary codes. Novice at the commit frozen beforehand (`7d89b06`; the `novice/` directory has not changed since) was run **once per seed on seeds 1 to 3, and the numbers were written down before the kinds were read**.

| seed | wrong facts | wrong guesses | hard kinds acquired (of 16) | new-operation questions right | composed questions right | controls: facts / guesses / refused |
|---|---|---|---|---|---|---|
| 1 | 0 | 0 | 1 | 7.1 % | 0 % | 62.5 / 18.1 / 19.4 % |
| 2 | 0 | 0 | 1 | 8.2 % | 3.5 % | 62.5 / 18.1 / 19.4 % |
| 3 | 0 | 0 | 0 | 0 % | 2.3 % | 62.5 / 18.1 / 19.4 % |

(All of those right answers are labeled guesses; none is a fact. Baby refuses every new-operation and composed question, as the generator's notes record.)

**What this says.** The honesty held on a set it was not developed against: 0 wrong facts and 0 wrong guesses on all three seeds. The capability did **not** transfer much. The single kind acquired is the base-3 digit sum, found as `f(x) = r + x mod 3, r = f(x div 3)`: the same recurrence as counting one bits, in another base, with no line of code that names a base. That is real transfer of the *mechanism*. But it is one kind in sixteen on two seeds and none on the third (there the right recurrence was found and rejected, because it saves 7.8 bits over the table against an error budget of 10: sixteen small answers are borderline evidence), and 15 of the 16 hard kinds stayed unexplained. The development result of five kinds in eighteen per seed should be read as an upper bound on what the mechanism does on kinds it was not shaped by.

**Why the other kinds were not reached** (found after the run, from the traces and the generator's notes):
- *Two earlier values.* Fibonacci mod `m` and the binomial coefficient mod `m` (Pascal's rule) depend on two earlier points; a recurrence here has one reduction.
- *A conditional step.* Collatz halves or triples depending on parity.
- *A step that is too long.* Josephus is `f(n, k) = (f(n - 1, k) + k) mod n` zero-based, but the exam counts places from 1, so the step is nine nodes; steps are searched up to five (seven for the six best reductions).
- *Multiplicative structure.* Totient, the number of distinct prime factors, the next prime and the sums and ranks built on them, partitions and Catalan numbers have no short recurrence in this language.
- *Reversal.* The base-3 digit reversal is not a function of a nearer value and a digit.

**A gap in the controls.** One control, `wrap` (`(k·a + c) mod m` with three constants), is refused on every seed by Novice and by baby, although it is expressible with the starting operations: seven nodes and constants that are in neither the plain list nor the five-node data-constants search. It is the same fraction (19.4 % of the control questions) on every seed.

**This set is now a development set too.** I have read it, so a third, blind set would be needed before claiming anything more about generalization. Any extension that lets Novice reach the kinds above (a step over two earlier values, a conditional) is a change made with these kinds in view.

### After the blind test: modular matching and a step over two earlier values

The blind test showed two gaps that were not about the hard kinds at all, and one that was. I closed them with the second set in view, which makes that set a development set from here on (see the end of this section).

**What was added.**
1. *Modular matching.* A kind whose answers are all below some number may be a rule reduced modulo it. The modulus is almost given by the data (just above the largest answer), and once the top operation is `mod m` the rest only has to be right up to a multiple of `m`, which a five-node search can do with the numbers in the data as constants. This closes the control gap (`(k·a + c) mod m` was refused on every seed by Novice and by baby; it is now explained, and the control role as a whole is fully answered: 76 to 78 % facts inside the range, the rest guesses beyond it, nothing refused), and it lets a step of a recurrence be reduced modulo a number.
2. *A step over two earlier values:* `f(p) = e(p, f(g1(p)), f(g2(p)))`, evaluated with a memo so that it does not branch for ever, for Fibonacci-style rules. A two-value step must use both values.
3. *Base cases.* A rule that holds from some point on has base cases at the start. The step may now miss a point or two (paid for as base cases, like any point the recurrence does not account for), and the hold-out treats the points a step does not explain from their true predecessors as given, not as predictions.
4. *Credit for the questions beyond the table.* A table cannot answer a point it has not seen; a rule can. A rule is credited as if half as many questions as there are table points were still to come, each costing a table the price of an answer nobody can guess (`log2` of the answer space). Without it the base-3 digit sum missed the error budget on one seed by 2 bits.
5. *A cap on effort.* Each stage of the search for a recurrence may cost at most 10,000 evaluations per bit of what the kind's table would cost (a rule cannot save more than the table).

**Results on the sets I have read** (seeds 1 to 3, scored per kind from how its answers actually did):

| set | wrong facts | wrong guesses | kinds answered correctly | notes |
|---|---|---|---|---|
| original exam | 0 | as before | unchanged | evaluations rose from about 24 M to 32 to 38 M |
| development set A | 0 | 1 in 3 seeds (integer square root, a spurious fit: 0 right, 1 wrong) | the one-bit count, the smallest power of two above `x`, one bits plus a constant, parity of the bit count (12 to 14 of 14 right each); trailing zeros (5 to 7 of 14, the rest refused); gcd and gcd/2 on seeds 1 to 3 (1 to 5 of 22: acquired but they reach few points on a sparse table of pairs) | trailing zeros is new; its step is a boundary case |
| set B (the blind set, now a development set) | 0 | 0 | the base-3 digit sum on all three seeds (12 to 14 of 14 right; it was 2 of 3); one odd fit (`totrank`) that answers 2 or 3 of 22 and gets none wrong | the control row is 100 % answered |

**Still not acquired:** Fibonacci mod `m` on the exam's tables (it is found on a table of 22 points, as a test shows, but on the exam's 16 points the re-fit during the hold-out comes out as a near-twin, `r + max(s, 1)`, so the evidence is ambiguous and it is correctly not accepted); the binomial coefficient (its reductions `(x - 1, y - 1)` are unusable as soon as `y = 0` is in the table); Collatz (a conditional); Josephus (a nine-node step); totient, distinct prime factors, the next prime, partitions, Catalan, and what depends on them; bitwise xor, and, or; the table lookup; the bit mirror.

**This is a development result.** Both sets of hard kinds have now been read by the author of the mechanism, so neither says how it does on kinds nobody has shaped it for. A third set, written without reading Novice's code and run once before anyone reads it, is the test that counts again.

### The third blind test (a third set, run once)

After the mechanism was extended with the second set in view, a third set of kinds was written by a separate session that had not read Novice's code (`tools/hidden_worlds_c.py`, pull request #36): 11 kinds that need a new operation, 5 composed on those, 4 controls the starting operations can express, 3 arbitrary codes. Novice at the commit frozen beforehand (`9c83ce8`; the `novice/` directory on `main` is identical to it) was run **once per seed on seeds 1 to 3, and the numbers were written down before the kinds were read.**

| seed | wrong facts | wrong guesses | hard questions answered right (248 each seed) | controls (56): facts / right guesses / wrong guesses / refused | kinds explained by a program (of 23) | evaluations |
|---|---|---|---|---|---|---|
| 1 | 0 | 2 (0.6 %) | **0** | 19.6 % / 1.8 % / 3.6 % / 75.0 % | 3 | 83.8 M |
| 2 | 0 | 1 (0.3 %) | **0** | 16.1 % / 0 % / 1.8 % / 82.1 % | 1 | 87.5 M |
| 3 | 0 | 1 (0.3 %) | **0** | 0 % / 0 % / 1.8 % / 98.2 % | 0 | 89.1 M |

**What this says.** The honesty of facts held (0 wrong facts on all three seeds). Nothing else did well:
- **No hard kind was acquired on any seed**: 0 of 15, against 5 to 7 of 18 on the set the mechanism was built on and 1 to 2 of 16 on the second. The acquisitions of the earlier sets were the kinds closest to the ones the mechanism was shaped by (counting bits, Euclid's rule, digit sums in a base). The kinds here need a conditional (hail, the game), a loop with a state over digits (longest run, the base with the first palindrome, the commonest digit), multiplicative structure (sum of divisors, the order of 2), or a longer step (derangements, Stirling numbers, tribonacci mod `m`), and none of those is within reach.

- **The work was about 85 M evaluations**, three times that of the earlier exams: with 23 kinds and almost none explained, every kind pays for the whole chain of failed searches.

**What I take from three sets.** The recurrence mechanism acquires a narrow family of rules reliably and honestly, and it does not generalize to kinds that need a conditional, a loop with a state, or a long step. ### After the third blind test: the cost of failing, and constants from the shape of the data

The third blind test left two things to fix that were not about the hard kinds: it had cost three times the work of the earlier exams because almost nothing was explained, and the controls (kinds the starting operations can express) were mostly refused. Both changes below were made with the third set in view, so it is a development set from here on.

**1. Effort scaled by what has paid off.** The profile was very concentrated: for a kind nothing explains, the closed-form stages cost 0.5 to 0.9 M evaluations and the recurrence stage 2.5 to 3.4 M (4.7 to 5.9 M for two arguments), about 80 % of the total, and the twentieth failing search cost as much as the first. Within the recurrence search, the small steps over one earlier value (where the recurrences that were found are found) cost about 0.6 M; the larger steps and the pairs of earlier values cost 1.0 to 1.5 M each. The dear stages are now given an allowance scaled by how often a recurrence has been found so far (twice the estimated chance of success, kept between a tenth and one and a half of the full allowance); the first stage always gets its full allowance. My first version scaled everything and lost recurrences on later kinds (the base-3 digit sum on one seed); scaling only the dear stages kept them. This is experience making failure cheaper, on a small scale: a system that keeps finding recurrences keeps searching for them, one that keeps failing stops spending.

**2. Constants from the shape of the data.** A kind of one argument that changes its slope at only a few places (a clamp, a threshold, a wrap, a fold) announces its constants: the slopes, the places where the slope changes, the gaps between those places (the period), each straight piece's constant term, and the largest answer. Those numbers become extra constants for a search of up to seven nodes. A kind that changes its slope at about every step (arbitrary codes) has no shape and gets nothing, which is what keeps the stage from running on kinds that cannot have one.

### After the fourth blind test: floors and moduli fitted directly

The fourth blind test left a sharp gap: floors of a line or plane with larger constants (`(43 * a + 65) div 12`, `(17 * a + 15 * b + 42) div 42`) and sums of multiples or quadratics reduced modulo a constant (`(46 * a * a + 43) mod 89`). Written in the language they take seven to nine nodes and constants no short list has, so no enumeration reaches them, and the shape stage (a few places where the slope changes) gives a floor nothing, since its step changes at almost every point. Each is a family with three or four integers, and the data pins them, so they are fitted instead of enumerated (`src/fit.rs`, a last stage after the shape stage):

- **Floor of a line or plane** `(m * x + n * y + c) div d`. Every pair of points that differ in one variable brackets that slope as a ratio (the floor of a line lifts by its slope times the distance, give or take less than 1); if the brackets cannot hold, nothing is tried, which is what keeps the stage cheap on the kinds that are not floors. Inside the brackets, each divisor up to 128 (64 for two variables) and each numerator give an interval for `c`, empty or not.
- **Sum of multiples modulo `k`** `(m * x + n * y + c) mod k`, for the moduli just above the largest answer; and **a quadratic of one variable modulo `k`**, where the second differences over consecutive numbers are all the same number modulo `k`, so `k` divides every difference between two of them (the moduli are the divisors of that gcd above the largest answer, since a sample of 16 residues rarely holds the largest).
- **Doubt must be kept.** Every member of the family that fits the data is kept, told apart on every point of the box out to just beyond the data (not on the sparse probe points the enumerations use, which called two close slopes the same program), and the members that give the highest and lowest value anywhere are always kept. Members that fit equally are not charged more than 3 bits over the cheapest, because the data does not choose between them: where they disagree, the answer is a guess, not a fact. My first version, without these two things, stated one wrong fact on one seed (a floor of `53 / 32` taken for `13 / 8`, which part ways at 24: 41 against 42). The exam found it, not a unit test: I could not reproduce it in a unit test after an exhaustive search over the held-out patterns I tried.

**Word order, as evidence (a first step).** Many reworded questions are the words of a taught question in a new order ("is mifuba sedavubi how" for "how is mifuba sedavubi"). A new order is now answered as a *guess*, never a fact, and only when the same sort of question (the words that many lessons share: the frame and the kind) was taught in two orders somewhere and the orders always agreed; the stated confidence is the Laplace estimate from those pairs. Where no order was ever taught twice, or two orders ever disagreed, it is refused. The other 90 % of the reworded questions use a frame that was not taught for that kind ("what is X K", "which X K", "give X K"); recognizing frames as equivalent from the other kinds they were taught for is the next step, and reading number words as numbers is the one after (the never-seen and beyond questions are arithmetic over number words, 3,768 of the 4,832 questions).

**Number words, found and not given (second step).** Most of the static exam (3,768 of 4,832 questions) is arithmetic over number words: "five bidevubi zero" is "five", with kinds whose names are invented. Novice now looks, before it learns the kinds, for words that are the answer of lesson after lesson and make up a kind that *adds* under some assignment of whole numbers to the words: one word that changes nothing when added, a second as the unit, and every lesson of the kind then fixes more words (a word that is only ever an answer, like "six", is fixed by the lessons that make it) until the lessons all hold or one fails (`src/numerals.rs`; nothing in it knows that "two" is a number, in any language). Words that stay free are tried from small numbers up and only the numbers every solution agrees on are kept; a second kind that adds under the same assignment can fix more. The lessons are then read again with those words as numbers, the kinds of numbers are learned as any other (subtraction and the difference, for example, are found by the learner on the numbers), and an answer that is a number is said as the word for it, or not at all if no lesson has a word for it ("six and six" is refused). Limits, plainly: addition is the structure looked for (a kind that is only an order does not fix a unit), and a number is a word only if a lesson says it.

Test first: five unit tests of the finder, two end to end (a held-out sum, a difference once the words are numbers, "zero and six" beyond the arguments taught, a result with no word refused, things still things; and no number words without a kind that adds). **The goldens caught my first version at once**: the finder treated written digits ("12") as words to learn, and the adaptive exam fell from 67.0 % to 36.3 % facts right; the check named the adaptive golden and the first hidden set as different, and digits are numbers already now. This is the first time Novice learns what words mean, by asking which meaning makes whole kinds simple programs: a rule that no line names, in the setting where baby won.

**Frames that mean the same (third step).** The reworded questions mostly ask a taught fact in a frame it was not taught in ("what is X K", "name X K", "give X K"). `src/frames.rs` learns frame words from the lessons themselves: two lessons with the same answer, one holding the words of the other and more, sharing a word that only a few lessons have (the thing asked about), are one fact in two wordings, and the extra words ("what", "how", "the", "of", "name") are counted as having changed nothing. A word counted six times or more is a frame word; what is left of a question without frame words is the fact it asks. A question whose content is a taught fact's, in a frame the fact was never taught in, is answered as surely as the evidence for its new frame words (the Laplace estimate of each one's pairs, multiplied; a fact only if that leaves less than 2^-10 of doubt, else a guess). Two things that came from the traps, not from planning: (1) my first version took any two lessons with the same answer as one fact, so a thing and two of its kinds that happened to share an answer made the name of a kind a "frame word", and a trap with two kinds at once ("the gedivubi of zudiba madevubi") was answered on seed 3, a seed I had not used until I scored it; wordings now have to be nested, one holding the other's words (no test could have found this: only a trap exam with that case). (2) A new order of the content words ("X K" for "K of X") is answered only if two orders of facts of the same kind were taught and agreed; a first version without that answered a pair of number words in the other order, which is the trap of the previous step. Test first: four tests of the finder, one end to end, 75 in all. Static exam: reworded 62.9 %, 61.4 % and 67.1 % facts right on seeds 1 to 3 (plus 10.0 %, 8.6 % and 12.9 % guesses; was 48.6 % facts), traps 0 of 140 answered and wrong facts 0 on all three. The 20 to 30 % still refused are mostly "what is X K" for kinds taught only as "K of X": nothing in those kinds shows that the order does not matter, and kinds of another family that do show it are not evidence for them (that is how a trap would get answered).

**The goldens** (`novice/golden/`, `check.sh`, as for baby): the static exam's predictions and judge table, and for the adaptive exam and the five sets of hidden worlds (seed 1 each) the judge's table, Novice's own account of its work (kinds explained, the programs, counted evaluations) and every reply. ### Number words that are not an addition: a kind that reads them

- **Number words: the finder found no word on any seed, so 0 of 6 new grammars.** The first family of each seed was bijective base 5 (no zero digit), balanced base 5 (digits from minus 2 to 2), a twenties-with-a-leftover count, and, for the families no kind reads, tally words, three places with a different set of digit words for each, and order-signed words with a subtractive pair. The finder's grammars are a hand-built list (sums, positional, least significant first, three-word mixed radix, multiplier words with minus); a set that invents other grammars gets none of the benefit. This is the plain answer to "does the number-word work generalize": it generalizes within the grammars it lists. Adding bijective and balanced digits (digit ranges other than zero to base minus one) and a connective word would cover two of the six; the better route, noted for later, is a finder that learns each word as a small arithmetic step (multiply the number so far by a constant and add a constant) instead of choosing among named grammars. Nothing was changed for this set: it is spent as a test.
- **Hard kinds: 0 of 12.** New-operation kinds here include three-number closed forms (the median, the greatest common divisor, a sum of three products modulo a prime), a powers-of-digits rule, sequences, a grid walk and a digit rule with a state. The modulus kind of set G has no counterpart that was acquired: a three-argument modular form is outside the two-argument fit stage.
- **Controls over digits are found** (a cube modulo a prime, a three-number average, a product over a quotient, a division then a remainder: 5 to 16 of 17 to 24 questions each); controls over number words are refused for the reason in the first point.

**Two defects found by an independent reviewer's notes (read after the numbers were recorded), each reproduced, then fixed test first.**
1. **A word-only answer from one unchecked source became a fact.** `TOLD q red` with a named source nobody had checked, then `ASK q`, gave a fact. A question with no numbers has no program to check a source against, so the answer is now kept apart and is only ever a guess (confidence one half); lessons and an unlabeled teacher stay facts. (The numeric path already weighed sources.)
2. **A correction did not reach the cached frame view.** My lazy rebuild of the frame lookups (a twentieth more lookups) meant that after `TOLD q blue` for a question that had been taught `red`, the same fact asked in another wording was still stated as `red`. A second answer for words that had one now rebuilds the frames at once.
Neither fix changed an answer on any exam run here (the generated worlds do not tell word-only answers from labeled sources or correct a cached wording). 91 tests; goldens A to G identical, set H added; sets F, G and H unchanged.

**Open, from the same notes and not done:** (1) the validation of a recurrence uses the held-out target to decide that a point is a base case and skip it, so an accepted validation can omit reachable errors (a clean outer split is the proposed repair, and it may lower the acquisition counts); (2) a table that is exactly the teaching table of a capped rule (`min(x + y, 8)`) is explained as `x + y` and states `9` as a fact at a corner of the box; (3) the adaptive judge does not count a guessed trap as a violation (the traps of set H were all refused, so no number here is affected). These are the next honesty items before more capability.

### Three honesty items from the review

An outside review (read after the eighth blind numbers were recorded) listed three things about how results are judged and stated. Each was reproduced, then handled test first.

1. **A corner of the box is not stated as a fact.** Teach every pair with `x + y <= 8` as `x + y` (also exactly the table of `min(x + y, 8)`) and the old rule stated `9` at `(8, 1)`: the pair is inside the box of the taught numbers, but no taught point reaches it. A fact is now stated only where some taught or told point is at least as large in every coordinate (`reached`), besides being inside the box and carrying all but 2^-10 of the belief; elsewhere inside the box it is a guess. The review proposed this as a conservative first policy, not a theorem: a rule that is capped or changes inside a hole is still not seen. **It costs coverage where nothing was wrong:** adaptive exam, facts right 67.0 % to 64.3 % (the difference became right guesses, 20.6 % to 23.4 %); static exam, never seen inside the range 96.9 % to 94.9 % facts (baby: 94.9 %); set F control facts 67 % to 64 to 66 %, set G about 39 % to 38 %. Wrong facts are 0 on every set before and after, so this changes what is claimed, not what was right. Test: `a_corner_of_the_box_that_no_taught_point_reaches_is_not_stated_as_a_fact`.
2. **Held-out validation of a recurrence skips points it gets wrong.** The check refits the step on part of the table; a held-out point that the refitted step does not explain even from its true predecessors is skipped as a base case, using the held-out answer to decide. A strict version (no skipping) loses one of the four recurrences of a small development table, so it is not adopted here. The skips are now counted, and the work account has a line: recurrences accepted with nothing skipped, and recurrences accepted only because such points were skipped (the small popcount table is the second kind, a table of 200 numbers the first). Answers do not change (a worked-out value of a recurrence was already a guess, never a fact); the count is the audit. Test: `a_recurrence_accepted_only_by_skipping_points_it_gets_wrong_is_counted_as_such`. Open: an outer split that never lets held-out answers choose the base cases, and its effect on acquisition counts.
3. **The adaptive judge did not count a guessed trap.** `baby exam adapt-drive` now counts any answer to a `trap` row, fact or guess, as a violation, never as capability (a guess that matches the dummy truth used to count as a right guess), prints `TRAPS answered (must be 0): N` when the stream has trap rows, and fails the honesty verdict if N is above 0. The baby's goldens are unchanged; Novice's were regenerated. Every trap of sets F, G and H was refused, so no earlier number changes. Test: `any_answer_to_a_trap_is_a_violation_even_a_guess_that_happens_to_match_its_dummy_truth`.

### The first experience-curve pilot (Novice only)

The review asked for the missing curve: what the system can do, and what it costs, as experience grows. `tools/experience_curve.py EXAM_DIR` is a first, small version for the hidden-worlds exams. The probe bank is the last third of the stream, never told. A fresh system is taught the lessons, asked (and told, or only asked) a prefix of the stream, and then asked the bank; capability and package energy above the idle draw are medians over repetitions. Honest limits: Novice only (the baby arm and a deep-copy of states are not built), package energy with the driver's own work in it, a few hundred questions per bank, hidden-worlds only, two repetitions in the numbers below.

**Experience as stream items (set G seed 1, 2 repetitions).** Right answers on the 195 eligible bank questions: 55 with no stream, 56 / 57 / 58 / 58 after a sixth, a third, a half, two thirds of the stream told, and 55 / 55 asked but not told (the control that separates learning from warmer caches). Counted evaluations 49.6 M at every checkpoint: the whole search happens when the lessons are taught, and being told the stream adds almost none. Serving the bank costs 3.5 mJ per question cold and 0.15 to 0.36 mJ warm; the cold figure is the first number-free question building the frame view (a one-time cost), not learning. So **on this set, experience in the stream buys about three right answers and does not make serving cheaper beyond warming up.**

**Experience as lessons taught (the same set).**

|---|---|---|---|---|

**Where the work goes.** Of the counted evaluations, **89 to 94 % are spent on kinds that never get a program** (set G seeds 1 to 3: 89, 94 and 89 %; set H seeds 1 and 2: 89 and 90 %; set F seed 1: 92 %); the kinds that are explained cost 3 to 6 M in all. The allowance of a kind grows with its table (10,000 evaluations per table bit), so more lessons for a kind with no rule cost more and teach nothing. This is the cost of failing, and it is the lever the review's feasibility check (M6) and learned search allocation (M7) aim at; the measurement to beat is the share above at identical replies.

### A feasibility check for the recurrence search, in shadow mode

The experience-curve pilot put 89 to 94 % of the counted work on kinds that never get a program; the traced stages of set G seed 1 put 57 % of it in the recurrence search (steps of size 7: 26 %, size 5: 20 %, pairs: 11 %) and 38 % in the closed forms. The review proposed a sound check before the step search. It is built in shadow mode: `NOVICE_SHADOW=1` makes each call of the search also log what the check would say (never acting on it) and the work the search then spent; `tools/shadow_report.py` summarizes the lines. Test first: with the shadow on, the counted evaluations, the kinds and every reply are identical to a run with it off (also checked on a whole exam: replies byte-identical; goldens unchanged), and a real recurrence is never what the sound check rejects.

**What the data say (24 exam runs, sets A to H seeds 1 to 3: 377 searches, 34 found a rule, 766 M evaluations in all).**
- **A sound certificate has almost no power.** Two checks can prove that no recurrence could be accepted: the cheapest reduction alone costs more than the table, the margin for chance and the answers to come (a cost bound, the same sum a recurrence must beat); or no reduction brings enough points down to a known one. The first rejects none of the failing searches; the second 3 of them, 0.02 % of the work. The reason is structural: a row contains the input, so no two rows can conflict, and the tables that fail are expensive to write, not cheap.
- **A soft feature of the table that separates in these exams is contradicted by a positive control.** The share of answers that are all different separates the 34 rules found (at most 47 % of the answers distinct) from the failures (up to 100 %): "more than half distinct" would have rejected no rule found and saved 40 % of the recurrence work. But a doubling rule (2^x, every answer different) is found by the search today (a test), so that gate would reject a true rule: the rules found in the exams so far all have few distinct answers, which is a property of the exams, not of recurrences. Another soft feature (the agreement of the answer minus the earlier answer within classes of the number's remainder) does not separate: rules found range from 0.46 to 1.00.
- **Conclusion:** no gate is switched on. A gate on what a cheap look at the table says is unsafe or empty; the work is spent where nothing cheap tells a failing kind from a succeeding one before the search runs. What is left is to change how much each search is allowed to spend from what the previous searches paid back (the review's learned allocation with protected exploration), measured at identical replies, and the shadow log is the instrument for it. 96 tests.

### A teacher who is consistently wrong about some facts (rung 3)

`baby exam adapt-write DIR --seed S --wrong P [--repeat 0.3]`: with probability P a fact is one the teacher is wrong about, and every time it tells that fact (any phrasing) it gives the same wrong answer, so a system cannot tell. The judge counts a wrong fact as a **repeat** (the same fact was wrongly told earlier: the system believed its teacher) or **elsewhere** (a fact never wrongly told: the teacher's mistakes damaged what the system knew; must be 0). Seeds 1 to 3 in each cell.

| teacher wrong about | Novice, 30 % re-asks | baby, 30 % re-asks (recorded for its skeptical exam driver) | Novice, no re-asks | baby, no re-asks |
|---|---|---|---|---|
| 10 % | 4 / 4 / 6 | 5 / 7 / 6 | 1 / 0 / 3 | not run |
| 20 % | 6 / 7 / 17 | 10 / 10 / 18 | 2 / 0 / 7 | 2 (seed 1 only) |
| 40 % | not run | 20 / 38 (two seeds) | 9 / 9 / 7 | not run |

Wrong facts about facts never wrongly told ("elsewhere", must be 0): **0 in every re-ask stream and in every no-re-ask stream but one** (seed 2 at 40 %, as in baby). Read plainly, the repeats are **on par with baby's**, not below them: the like-for-like cells are close, and the one stream where both ran (seed 1, 20 %, no re-asks) gives 2 and 2. **Every remaining wrong fact I checked is in one of the six kinds that have no rule to check against** (a prime test, an exclusive-or, four arbitrary codes): a single source cannot catch a mistake there by any means, as baby's notes also found, and a second independent source is what rung 4 is for (below).

**What it costs: coverage.** On that shared stream (seed 1, 20 %, no re-asks), baby states 59.3 % as right facts and gives 25.0 % right guesses (2.9 % wrong guesses, 12.5 % refused), right across the thirds 82.9 → 84.0 %. Novice states 58.8 % as right facts, 19.1 % right guesses (1.5 % wrong), **20.3 % refused**, 69.2 → 82.4 % across the stream. So Novice is as sure of its facts and wrong less often when it guesses, but it declines where baby guesses and is right. The first version of this rung refused 33 % there: the record of how its guesses outside the taught region had turned out was shared by all kinds, so kinds whose rule really changes (and a teacher who is wrong a fifth of the time) dragged the confidence of the stable kinds below one half. Each kind now keeps its own record, shrunk toward the shared one, which brought it to 20 %. The rest is the price of not guessing from a poor record, and is open.

**How it works, and why no count is tuned.** A told answer that disagrees with a program does not remove the program. The program pays the price of an exception: the bits to say which point (`log2(points + 1)`) plus the bits to write the odd answer. Rivals that agree with the told answer gain on it. One slip costs the believed program about 14 bits, and the rival that explains a real change of rule (a ceiling at 30) costs about 16 bits more to write, so one contradiction changes nothing and two that a rival explains together win. That is baby's hand-set "three coherent answers", derived from the costs. A point where a told answer was refused is never stated as a fact, only guessed. Saying the same thing again (a re-ask, another phrasing) is counted, not weighed twice. On honest streams the learner is a little slower to adopt a rule that really changed (wrong guesses 1.1 % against 0.6 % before this rung).

**Caveats, plainly.**
- **The exam is tidy and was written by the same author as the learner.** The kinds are small arithmetic rules over the integers 0 to 15. The operations Novice starts with (`+ - * min max div mod`) are my choice and fit that domain; that the exam is passed says nothing about worlds the starting operations cannot express. Two of the six unexplainable kinds (a prime test and an exclusive-or) have a rule that the starting operations cannot say; rung 5 is where that is tested properly.
- **Words are only a first step toward a language that grows.** Earlier explanations become words; no new primitive is ever made. The two words are compositions of the starting operations.
- **Joules are upper bounds from one machine and one seed.** Nothing here yet shows that adapting makes anything cheaper in joules; the composition result is about the cost of learning a kind, not of answering a question (which was never expensive).
- **Sources must err independently.** Two sources that make the same mistake are believed, and a reliability can only be measured where some kind has a rule. The second source in the exam is generated to be independent.
- **The static exam is passed on honesty only.** Novice answers what was taught word for word and refuses the rest (see above). A teacher who is wrong about a whole kind of thing, not about some facts, is not caught (nothing inside one source can catch it).
- **Guesses are labeled but crudely calibrated.** Outside the region it has seen, the confidence it states is the kind's own record of right guesses, shrunk toward the shared record at that distance. The judge has not yet been asked whether the stated confidences match the realized rates.
- **The failed searches are still most of what is left**: the six lookup kinds are searched, fail, and are searched again as they grow.

## Mistakes and dead ends (newest first)

- **Two lessons that share an answer are not one fact.** The first frame finder counted every pair with a common answer and a common rare word; a thing with two of its kinds at the same answer made the name of a kind look like a frame word, and a trap with two kinds at once was answered (seed 3 only). The pair has to be nested now. Lesson: score every seed of an exam before believing one.
- **Digits are not words to learn.** My first finder of number words took the written digits of the adaptive exam for words, translated its answers, and then refused every result without a word for it: 67.0 % fell to 36.3 %. The unit tests did not see it because they had no digit lessons; the goldens did. A new test pins it.
- **I never ran the static exam, and it found 2,416 wrong facts.** Every honesty check I had was on the adaptive exam and the hidden worlds, where every question has numbers. The first static run answered other facts' answers to questions taught word for word, because a question without numbers has no key to tell it from another that shares a word. Rule from this: run every tier of the entry exam on a new system before writing that it is honest.
- **A fitted family without doubt stated a wrong fact.** The first version of the floor fit kept one program per behavior on the sparse probe points, so a slope of `13 / 8` that agrees with the data hid the true `53 / 32` that differs from it first at 24, and the system said 41 where the truth was 42 (one wrong fact, set D seed 3). The members are now told apart on every point out to just beyond the data, the extremes are always kept, and equal fits are charged at most 3 bits apart. A second mistake in the same stage: bounding the slopes by the range of the answers instead of by pairs of points tripled the cost of the original exam.
- **Scaling all the effort by the success rate lost recurrences.** My first version of the adaptive effort scaled every stage by how often recurrences had been found. The base-3 digit sum then disappeared on one seed (and something else on a seed of the first development set), because by the time a late kind was reached the estimate had fallen so far that even the cheap first stage was starved. The first stage always gets its full allowance now; the traces showed it costs about 0.6 M and that the larger steps and the pairs cost 1.0 to 1.5 M each.
- **The constant 26.** The shape constants first missed the intercept of the second line segment (26 for `max(x, 3x - 26)`), so a unit test of a threshold failed even though the exam found the same shape by luck; each straight piece's constant term is now one of the extracted numbers.

- **Extending for the second set, in the order the mistakes came.** (1) A step over two earlier values first found nothing for Fibonacci because the eight cheapest reductions are degenerate (the constants 0 and 1, `min(x, 1)`, `x mod 2`): reductions that collapse the points are base cases, not steps, and are now excluded from pairs. (2) Fibonacci's rule does not hold at `x = 1`, so an exact fit failed on the boundary row; a step may now miss a point or two, but allowing that for every candidate tripled the work, so it is allowed only for the cheapest few. (3) The cost model compared a rule with a table that is cheap because the answers are small, and so rejected a correct rule that the table could not extend; the credit for the questions beyond the table fixed that, at the risk of accepting spurious fits, which a degenerate pair (`min(x, s)` that never used `r`) showed at once as a wrong guess: a two-value step must use both values. (4) My first effort cap was shared by all stages, so the first stage spent it and the pairs were never tried. (5) A trace line subtracted unsigned numbers and printed 7.2e16 bits.

- **Rung 5, in the order I made them.** (1) A recurrence was tried before the closed-form search could use learned words, and it preempted a better explanation: for the sum-of-squares-plus-one kind it accepted a true identity that reaches few points (13 of 18 questions refused). Now a recurrence is the last resort. (2) The table was priced as if every answer cost bits in proportion to its size; kinds with small answers then looked more compressible than they were, and spurious recurrences saved 25 to 57 bits. Now the table is priced with a code that learns the distribution of the answers. (3) I ranked candidate reductions by how much they narrow the answer, which any reduction that maps every point to a different point wins trivially; they are now ranked by cost among those that reach enough points. (4) My first hold-out used a hash that hid or kept consecutive small numbers together, leaving unary kinds with no training rows at all, and a single hold-out has no power on 16 points; the check now runs over four rounds. (5) Accepting the cheapest candidate and giving up when it failed validation lost genuine recurrences whose cheaper cousins were partial truths (`r + 1, r = f(x mod min(x, 8))` is right for 9 to 15 and 17); candidates are now tried in cost order. (6) A symmetry (`f(x, y) = f(y, x)`) beat Euclid's rule on a dense table because it is cheaper and true; both are kept as rivals, and a recurrence whose chain reaches nothing abstains instead of counting as doubt. (7) I required a reduction to reach 40 % of the table, which is far above what the true reduction reaches on a sparse table of pairs.

- **Failing got dearer as the library grew, and I guessed the cause wrong twice.** In the curriculum measurement the kinds that cannot be explained cost 4.7 times as much with a library as without in the first measurement (batch 9: 2.87 M evaluations against 0.61 M; 2.19 M after my first two fixes). My first explanation (a word with all-distinct outputs makes "the answer is a function of the word's output" trivially true; unsolved kinds were retried on every new word) was partly right and moved nothing, so I added a collision requirement and a doubling back-off and measured again: barely changed. My second (every new kind's first blind search ran over a larger alphabet because earned words were in it) was also not the cause: the result was identical. Only a trace of what each kind was charged showed it: after the cheap search failed, a blind enumeration over all 33 offered words cost 433 K per unary kind and about 13 M per two-input kind. Now composition (one lookup per word) uses every word on offer, and blind enumeration only the words that have earned their place; the cost of failing is 4 to 10 % above the control. The collision requirement and the back-off stay (they are sound), and the first search no longer carries words.

- **I first compared Novice with the wrong baby numbers and claimed it beat baby on repeats.** The recorded baby figures (5/7/6, 10/10/18) are for streams with 30 % re-asks; I set them against Novice runs without re-asks. When I ran baby on a stream without re-asks, it matched Novice (2 and 2), and the like-for-like cells are close. The claim was in the commit message of the first rung-3 commit and in the description of the pull request that carried it; the pull request description is corrected, the commit message stays as pushed (history is not rewritten), and the table above states what was compared with what. The same run showed that Novice's refusals under a wrong teacher were far above baby's (33 % against 12.5 %), which led to the per-kind record.

- **A repeated answer was weighed as new evidence.** My first version of the exception price penalized the believed program every time a wrong answer was told, including when the same wrong answer came again as a re-ask, while programs found by editing were priced against it once. The believed rule (`div(x, 10)`) then lost to a rival (`div(x, 9)`) that happened to agree with some wrong answers, and the system stated a wrong fact about a fact the teacher had never got wrong (1 on one of six streams; the must-be-zero column). Fixed by weighing a (question, answer) pair once; the same stream now has 0.

- **Rivals found only by editing the best program gave a wrong fact.** To save work I replaced the enumeration of larger programs by edits of the best one (wrap it in an operation, swap a constant). Cost fell from 486 M to 323 M evaluations and the exam was unchanged on seed 1, but on seed 2 the first stream question, a digit-sum kind, was answered `0` as a fact where the truth was `9`. The lessons skipped 7, 9 and 10, `x mod 9` fits every one of them, and it is about 7 bits cheaper to write than the real rule; the real rule is not one edit away from it. The enumeration had been keeping it as a rival with enough belief to stop the fact. The right completeness rule is a cost rule: any program within `RISK_BITS` of the best can keep a fact from being stated and must be considered; edits are an addition (they find ceilings and wrap-arounds that cost many bits more), not a substitute. Restored, made cheap another way (the last level is only checked), and pinned by a test built from that exact case.
- **The widest search (every number in the data as a constant) was dead weight once contradictions are repaired by editing.** It cost 65 M evaluations, almost all failing on the lookup kinds, and removing it changed no answer on three seeds.

- **Grouping by the rarest word was wrong.** My first version named a question's kind by its rarest word. It passed the exam, because the kind word appears three times per fact while "is" appears everywhere. A small test world broke it at once: there "is" was rarer than the kind word and one kind split into three groups. Replaced by the rule in the table above, which gives byte-identical exam results and passes the small world.
- **It stated a negative result for a kind that never showed one** (`3 - 5` as `-1`, guessed at 99 %), and answered a question that contained a word it had never met. Both were caught by the tests I wrote for them before recording the results, and both now refuse.
- **My first expectation for the saturating sum was wrong.** I expected a fact one step outside the region; the system rightly guessed. The sequence it follows is worth recording: after the first contradiction a rival (`y + min(x, 10)`) that fits all the data by luck survives and is believed; the second contradiction removes it, and only then is the ceiling found.
- **First run of the learner** (before words and before constants named by refuted programs): 74.9 → 80.2 %, stage-2 kinds 52 → 72 %, deceptive kinds 66 %. Both additions were made because of these numbers.

## Rules (the ones that protect the results)

- **WRONG is reported apart from refused**, and a stated fact that is wrong must stay at 0. A guess may be wrong; it must say how sure it is.
- **Add must-refuse questions with every capability** and think adversarially about what could be answered but should not be.
- **Record mistakes and rejected hypotheses here as they happen.** Dead ends are part of the record. This file is the notebook for Novice, newest section first, once there is something to put in it.
- **Report joules as upper bounds** unless the machine was quiet; never build or compile while a measurement runs; energy exists only where the CPU's counter is readable (Linux).
- **Say what is hand-built.** Every constant that was chosen, not found, is listed with the rung that is supposed to remove it.

## Platforms

Novice is checked on Linux x86_64 and aarch64 for every change (tier 1). macOS, Windows and musl are built and tested weekly and on demand (tier 2); wider coverage (the BSDs, WebAssembly, 32-bit, big-endian) is added at milestones, once there is a result worth keeping identical. Because decisions use integers only, identical results across platforms are expected by design and checked at milestones, not on every commit. baby's own matrix is unchanged and runs when baby changes.
